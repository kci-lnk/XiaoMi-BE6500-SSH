# 小米 BE6500 SSH 工具

在 macOS 或 Linux 终端运行。先确定要操作的**那一台路由器**的管理地址。有线 Mesh 的主路由和子节点各有自己的地址，验证其中一台只能确认该台的状态。

| 你想做什么 | 在项目目录运行 | 需要准备 |
| --- | --- | --- |
| 确认能否以 root 登录 | `./miwifi-ssh.sh --check 192.168.31.1` | 目标节点的地址、SSH 密码或密钥、OpenSSH 客户端 |
| 用旧版固件接口尝试开启 SSH | `./miwifi-ssh.sh` | 目标节点的管理会话 STOK、地址、机身序列号，以及 curl、Python 3、OpenSSL 和 OpenSSH 客户端 |

## 已有 SSH，验证登录

把下面的地址换成目标节点的地址。首次连接时，按 OpenSSH 提示核对主机密钥。

```sh
./miwifi-ssh.sh --check 192.168.31.1
```

脚本以 root 登录并执行 `id -u`。只有远端返回 `0` 才显示“已验证”并以状态码 0 退出。此命令不会修改路由器配置。

## 尚未开启 SSH，尝试旧版接口

```sh
./miwifi-ssh.sh
```

1. 登录目标节点的 Web 管理后台，从登录后的网址复制 `stok=` 后面的会话值。
2. 按提示输入 STOK、目标节点地址和该节点机身上的序列号。直接回车会使用默认地址 `192.168.31.1`，操作子节点时请填写子节点地址。
3. 脚本分四步修改并启动 SSH 服务。任一步失败都会立即退出，之前已执行的步骤可能已经生效。四步均通过后，脚本会尝试实际登录，并以登录验证结果为准。

## 遇到 1523 怎么办？

在两台 BE6500（RN02）的现场测试中，固件 **1.0.43** 和 **1.0.64** 都对旧接口返回了 `1523`。遇到这个结果，当前版本会显示错误并停止，没有自动切换的开启方式。

如果节点之前已经开启过 SSH，直接用上面的 `--check` 验证。若验证时出现 `Permission denied`，说明 SSH 服务已经响应，请核对该节点自己的 root 凭据。若连接超时，请先核对节点地址及本机到节点的网络连接。
